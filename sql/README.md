# SQL Analysis — Olist Brazilian E-Commerce

## Overview

This folder contains the MySQL component of the Olist Brazilian E-Commerce Business Analytics project.

The SQL analysis uses cleaned and integrated datasets exported by the Python notebooks. It builds typed analytical views, validates the imported data, and examines sales, delivery performance, customers, sellers, product categories, basket composition, and review satisfaction.

The analysis is descriptive and historical. Associations found in the data should not be interpreted as proof of causation or guaranteed future performance.

## Technology

* MySQL 8.4
* MySQL Workbench
* Common table expressions
* Window functions
* Analytical views
* Conditional aggregation
* Data-quality validation queries
* Market-basket association metrics

## SQL files

The files should be executed in numerical order.

### `01_database_setup.sql`

* Active database and MySQL version
* Imported row counts
* Unique key counts
* Table availability
* Available columns
* Initial data types
* Import completeness

Creates reusable typed views from the imported CSV tables.

The main views are:

* `vw_order_analytics`
* `vw_customer_analytics`
* `vw_seller_analytics`
* `vw_order_items`
* `vw_products`
* `vw_category_translation`

These views convert imported text fields into suitable analytical types, including:

* Dates and timestamps
* Monetary values
* Counts
* Review scores
* Delivery metrics
* Binary analytical flags

### `03_data_quality_checks.sql`

Performs final SQL-level data-quality validation.

The checks cover:

* Primary-key uniqueness
* Missing keys
* Referential integrity
* Monetary reconciliation
* Review-score ranges
* Delivery-rate ranges
* Timestamp consistency flags
* Related-table coverage

### `04_sales_performance.sql`

Analyzes overall and monthly sales performance.

The script includes:

* Executive sales overview
* Order-status distribution
* Monthly delivered orders
* Monthly delivered payment value
* Month-over-month growth
* Comparable 2017 and 2018 performance
* Payment-method performance
* Final sales reconciliation

### `05_delivery_performance.sql`

Examines order delivery performance.

The script includes:

* Valid delivery records
* On-time and late deliveries
* Late-delivery rate
* Delivery-delay severity
* Review scores by delivery performance
* Monthly late-delivery trends
* Rolling three-month late-delivery rates
* Customer-state delivery performance
* Final delivery validation

### `06_customer_analysis.sql`

Analyzes customer activity, concentration, and recency.

The script includes:

* Customer overview
* One-time and repeat customers
* Geographic customer distribution
* Customer payment-value concentration
* Recency groups
* Highest-value repeat customers
* Customer-level validation

Customer recency is calculated using a fixed historical snapshot date of October 18, 2018. It should not be interpreted as current customer activity or confirmed churn.

### `07_seller_performance.sql`

Analyzes seller activity and operational performance.

The script creates:

* `vw_seller_order_performance`
* `vw_sql_seller_performance`

The analysis includes:

* Seller overview
* Seller product-value concentration
* Reliable-seller performance groups
* Priority investigation candidates
* Seller-state performance
* Seller-level reconciliation

Priority candidates are sellers with both a higher-than-benchmark late-delivery rate and a lower-than-benchmark review score. This classification identifies investigation candidates, not confirmed underperformers.

### `08_product_category_analysis.sql`

Analyzes product categories and order-basket composition.

The script creates:

* `vw_order_item_categories`
* `vw_order_categories`
* `vw_order_basket_profile`
* `vw_category_pair_metrics`

The analysis includes:

* Product-category integration
* Category order support
* Category product-value contribution
* Category delivery and satisfaction metrics
* Multi-item and multi-category baskets
* Unordered category pairs
* Directional association rules
* Support, confidence, and lift
* Threshold-sensitivity analysis
* Final product and basket validation

Category-pair associations are exploratory because multi-category orders are uncommon and pair support is low.

### `09_review_satisfaction.sql`

Analyzes order-level review satisfaction.

The script creates:

* `vw_review_satisfaction`

The analysis includes:

* Review coverage
* Review-score distribution
* Satisfaction groups
* Single-review and multiple-review orders
* Written feedback versus rating-only reviews
* Review performance by order status
* Satisfaction by delivery performance
* Delay-severity analysis
* Monthly satisfaction trends
* State-level satisfaction
* Low-review and late-delivery overlap
* Final review validation

Average order review score is used for the order-level satisfaction classification. The latest individual review score is retained for the 1–5 score distribution.

## Main findings

### Sales

Delivered orders account for 97.02% of all orders. Delivered orders represent approximately R$15.42 million in payment value and R$13.22 million in product value.

Monthly performance generally increased during the observed period, although growth was uneven and included seasonal peaks. The data covers a historical period and should not be treated as a current revenue forecast.

### Delivery performance

Among the 96,281 orders with valid delivery metrics, 6,531 were delivered late, producing an overall late-delivery rate of 6.78%.

Late-delivery performance varies across months, states, sellers, and product categories. Orders delivered late are also associated with lower review scores, but the SQL analysis does not establish a causal relationship.

### Customers

The analysis represents 96,096 unique customers. Most customers placed only one observed order, while repeat customers represent a relatively small portion of the customer base.

Customer recency is calculated relative to the end of the historical observation period. Recency groups are behavioral summaries rather than confirmed active, inactive, or churned customer labels.

### Sellers

The dataset contains 3,095 sellers. Performance evaluation is restricted to sellers meeting minimum reliability thresholds so that very small sellers do not dominate the rankings.

Among 417 reliable sellers, 111 are included in the higher-late-rate and lower-review-score group. These sellers represent investigation candidates rather than confirmed underperformers.

### Product categories

`bed_bath_table` appears in the largest number of orders, while categories such as `health_beauty`, `watches_gifts`, and `bed_bath_table` contribute substantial product value.

Only 0.80% of item-containing orders include multiple product categories. Because category combinations are rare, market-basket rules have low support and should be interpreted cautiously.

The strongest reliable positive association is between `home_confort` and `bed_bath_table`, with a lift of approximately 1.13. This is a modest descriptive association, not evidence of a guaranteed cross-selling effect.

### Review satisfaction

The delivered-order review analysis contains 95,832 orders. Of these, 12,273 received an average review score of 1 or 2, producing a low-review rate of 12.81%.

Written feedback is more common among dissatisfied customers, and late deliveries are associated with lower review scores. These results identify patterns for further investigation but do not prove why individual customers submitted low reviews.

## Important analytical definitions

### Delivered order

An order whose status is `delivered`.

### Valid delivery order

A delivered order with the timestamps required for delivery-duration analysis and without an invalid timestamp sequence.

### Late delivery

A valid delivered order where the customer delivery timestamp occurs after the estimated delivery date.

### Low satisfaction

An order with an average review score of 1 or 2.

### Reliable seller

A seller meeting the minimum order, review, and delivery-record thresholds used in the seller-performance analysis.

### Product value

The sum of item prices. Freight is analyzed separately unless explicitly included in an item-total calculation.

### Payment value

The total amount recorded in the payment data. Payment value and product value represent different business measures and should not be treated as interchangeable.

### Category support

The percentage of item-containing orders that include a given product category.

### Pair support

The percentage of item-containing orders that include both categories in a category pair.

### Confidence

The proportion of orders containing the antecedent category that also contain the consequent category.

### Lift

The observed category-pair frequency relative to the frequency expected if the categories occurred independently.

## Limitations

* The dataset is historical and mainly covers 2017 through August 2018.
* The first and final calendar months are incomplete and are excluded from several trend comparisons.
* Review metrics are unavailable for orders without review records.
* Delivery metrics exclude orders with missing or invalid operational timestamps.
* Multiple review records are summarized at the order level.
* Seller rankings use reliability thresholds and do not represent every seller equally.
* Customer recency is an observed historical proxy, not confirmed churn.
* Market-basket findings are limited by the small number of multi-category orders.
* SQL results describe associations and should not be interpreted as causal business effects.
* Currency values are reported in Brazilian reais.
